### 2.2 `253b0912` 色域矩阵 / Log 曲线 / DNG 预览——**方向正确，非本轮症状主因**

对齐了 gamut 矩阵与 Log 曲线、修 DNG 内嵌预览管线（对应主报告 C2/C3 类问题）。对图 1/图 2 的症状无直接影响。

### 2.3 `47819f26` 线性 raw DNG 隔离 + LSC 绿通道 + 色度降噪——**一处正确、一处需改**

- ✅ **色度降噪回到 WB 空间**：`wb_input = input·wb → YUV → bilateral/desat → 逆变换 → /wb`。这修掉了我诊断的"在未白平衡空间做色度降噪"（未 WB 中性色的色度矢量是 `U≈−0.081s, V≈−0.223s`，是一根**指向绿侧的大偏置**，阈值/滤波都作用在偏置上）。
- ✅ 删除了 raw 域 knee 的**逐通道**版本。
- ⚠️ **但色度降噪的阈值仍是绝对值**：`sig2=100`、`threshold=25000`、`factor=1.4` 都没变。3 EV 欠曝时信号整体缩小 8×，`|input| < 25000` 几乎恒真 → **去饱和在整幅画面全强度生效**，与上游调参时的工况完全不同。这是图 1 天花板那种**低频青绿色斑块**的合理来源（15×15 双重高斯的尺度也在 100+ px 量级）。
- ⚠️ 同时 LSC 的**位置**被移动（见 2.5）。

### 2.4 `c26ab617` 高光绿裁剪 + raw video log shader + 内存——**修对了一个真 bug**

- ✅ 去掉了 `wb_input` 的 `u16_sat`：原实现 `u16_sat(input·wb.r)` 会在 `wb.r>1` 时把 R 提前裁到 65535，反除回来后**高光 R 偏低**（就是"highlight green clipping"）。
- ✅ `if (num_passes <= 0) return input;`：fast 档（ISO<400）不再做无意义的 RGB→YUV→RGB 往返。
- ⚪ `thread_local`→新建 vector：换来内存可回收，代价是每张的分配抖动，属可接受权衡。

### 2.5 `c686aaed` 环带 + 角部裁剪（**你这两张图之后的提交**）——**正确但方案有副作用**

- ✅ 把 raw 域 knee 从"逐通道压缩"改为"**联合比例**"（`scale = compressed/max_ch` 统一乘三通道）→ 消除色相偏移。
  **我在真实 DNG 上量到了这个色相偏移**：最亮区（max=61414>50000）R/G=0.822、B/G=0.745，而周围 r=100px 外是 0.580/0.505 —— 逐通道 knee 确实把高光推成"偏白/偏品红"。联合比例能消除**色相**偏移（但保留**亮度**环）。
- ❌ **LSC 从 Bayer 域移到了去马赛克之后**（`apply_lsc(demosaic_output, ...)`，按输出通道取 ch0 / avg(ch1,ch2) / ch3）。三个问题：
  1. **语义**：LSC 是**逐 CFA 站点**的增益（含 color shading）。放到 demosaic 之后，"每个 CFA 站点各乘自己的增益"变成"每个输出通道乘一个平滑增益"。因为增益变化远慢于 5×5 插值窗口，**一阶近似成立**（误差是二阶、约百分之几），但**去马赛克本身看到的是未校正数据**，角部（渐晕最大处）会留下残余色彩渐晕 → 与"四角偏色"一致。
  2. **掩盖而非解决通道序问题**：`gain_g = 0.5*(ch1+ch2)` 让 G1/G2 交换问题失效（这点是好的），但 **R/B 仍然直接取 ch0/ch3**。本机设备是 **BGGR**（我从官方 Bayer DNG 的 `CFAPattern=[Blue,Green][Green,Red]` 读出），而仓库历史里 `4a524839` 明确记录过设备可能按**物理序**填充 LSC（对 BGGR 即 `[B, Gb, Gr, R]`）。若本机是物理序，则现在 **R 拿到 B 的渐晕增益、B 拿到 R 的**→ 角部平滑的 R/B 色彩渐晕错误。
  3. 去马赛克之后施加 LSC，会让**膝点/裁剪**作用在已放大的角部像素上（角部更容易进入裁剪区）。
- ⚠️ **线性 DNG 里仍保留 knee=50000 的非线性**：联合比例消除了色相偏移，但"线性 raw 里有一条非线性拐点"仍违反 DNG 的线性参考模型，并会留下**亮度环**（contour）。对 DNG 的正确做法是**完全不压缩**。

## 5. 建议的修改（按优先级，可直接落在本 PR 内）

**P0（影响 DNG 观感，必须先做）**

1. **LSC 移回 Bayer 域**（`apply_lsc(black_white_level_output, ...)`，在 `demosaic` 之前），并按 `SENSOR_INFO_COLOR_FILTER_ARRANGEMENT` 在 JNI 侧做**显式通道重映射**（或用"两绿取平均 + 明确 R/B 序"的方式），**不要用假设代替判定**。
   若暂时无法判定设备序，先做一个开关：`logical`（默认）/`physical`（对 BGGR = `[B,Gb,Gr,R]`），并用 §6-3 的日志二选一。
2. **色度降噪阈值随曝光归一**：把 `digitalGain`（或等效的欠曝比）传进 Halide，把 `threshold=25000`、`sig2=100`、`factor=1.4` 改为乘 `1/effGain` 的相对量；或在进入降噪前把数据归一化到固定参考电平、之后再还原。
3. **DNG 路径去掉非线性**：`apply_lsc` 里的 knee 只在**显示/JPEG**链路使用；线性 DNG 输出纯线性数据（DNG 规范要求 raw→linear reference 为线性）。

**P1（暗部偏色的根因）**

4. **确认并消除暗部 R 亏缺**：先跑 §6 的三个判定实验定位是 ①/③/④ 中的哪一个；若是 ③（负瓣核整流），可考虑
   (a) **把 WB 放到 demosaic 之前**（上游 hdr-plus 的原始做法，R/B 先被放大、整流相对变小；代价：DNG 需要再除回来，或按 `AsShotNeutral` 契约调整），
   (b) 或对负瓣核的输出改用**对称软限幅**而不是 `u16_sat` 单向截断，
   (c) 或用 G 引导的色差插值（避免负瓣核）。
5. **`desaturate_noise` 的 15×15 双重高斯**：半径过大（低频色斑来源），建议降到 5–7 或改为引导滤波，并只在真正低信噪比区域启用。

**P2（可观测性与回归）**

6. 把 §6 的三项设备日志与 §3 的离线判据固化成脚本/断言（我提供的 `.tmp/verify/dng_diag.py` 可直接复用），
   每次改管线都对同一场景出一张 DNG 做 A/B。
