## 0. 最重要的发现：这两张 JPEG 走的是 **F-Log2 + Velvia 3D LUT** 路径

两张 JPEG 的 Exif `UserComment` 原文：

```json
{"log":"F-Log2","lut":"FLog2 to Velvia 33grid V.1.00.cube","exposure":0,"contrast":0,"saturation":0,
 "highlights":0,"shadows":0,"whites":0,"blacks":0,"digital_gain":4.5288…}
{"log":"F-Log2","lut":"FLog2 to Velvia 33grid V.1.00.cube", … "digital_gain":6.8090…}
```

对应代码里的分支（`process_and_save_image`）：`targetLog = LOG_CURVES.indexOf("F-Log2") = 3` →
**WB → 高光去饱和 → `digitalGain` → CCM → sRGB→XYZ→Rec709 → `f_log2()`（对数编码）→ 对比/饱和/HSWB → `apply_lut(Velvia 3D LUT)`**。
也就是说：**这两张 JPEG 的颜色主要由"对数编码 + 胶片 LUT"决定，而不是普通的色调引擎**。
（`digital_gain` 4.53 / 6.81 也直接证实了欠曝策略：分别欠曝约 2.18 EV / 2.77 EV。）

> 修正：我一开始按默认的 PBR Neutral 引擎去解释暗部偏绿，**方向对但路径错了**——这两张 JPEG 根本没走那条分支。下面是按**真实路径**做的端到端复现。

## 1. 端到端复现：轻微的场景偏色 → 被 LUT 放大

复现脚本 `.tmp/verify/jpeg_path_repro.py`（DNG → WB → gain → CCM（由 `ColorMatrix1` 与 `AsShotNeutral` 反推）→ F-Log2 → Velvia LUT）：

| 区域 | **DNG 白平衡后** R/G, B/G | **复现管线** R/G, B/G | **App JPEG 实测** R/G, B/G |
|---|---|---|---|
| 墙面 亮部(靠窗) | 0.879, 0.890 | 0.478, 0.588 | 0.667, 0.634 |
| 墙面 中调 | 0.929, 0.932 | 0.654, 0.747 | 0.787, 0.775 |
| 沙发(白布) | 0.939, 0.929 | 0.678, 0.787 | 0.823, 0.773 |
| 桌面/窗边(最亮) | 0.908, 1.089 | 1.103, 0.863 | 0.937, 1.044 |

- 复现与实测**同方向、同量级**（差异来自 CCM 反推的数值误差与 JPEG 4:2:2 色度抽样）；
- 关键是三列对比：**场景本身只偏 7–12%，到 JPEG 里变成偏 25–50%。**

### 直接测 LUT：它是放大器

对同一亮度、输入轻微偏绿（R=B=0.915·G）做 LUT：

| 输入电平(F-Log2 码值) | 输入 R/G | **输出 R/G** | 放大倍数 |
|---|---|---|---|
| 0.20 | 0.915 | **0.401** | **2.28×** |
| 0.25 | 0.915 | 0.468 | 1.95× |
| 0.30 | 0.915 | 0.440 | 2.08× |
| 0.35 | 0.915 | 0.483 | 1.89× |
| 0.45 | 0.915 | 0.627 | 1.46× |
| 0.60 | 0.915 | 0.631 | 1.45× |

- 该 LUT 对**完全中性**输入在 0.25–0.80 区间是保中性的（实测 R/G、B/G 0.97–1.00），
  但对**带轻微色偏**的输入会把色度放大 **1.5–2.3 倍**——这正是"高饱和胶片 LUT"的正常行为（Velvia 以浓绿著称）。
- 而本场景被欠曝 2.2–2.8 EV 后，画面**大量内容落在 LUT 的低码值区（≤0.35）**，恰好是放大倍数最大（≈2×）的区间。

**因此：App JPEG 里的"暗部发绿/发青"= ①场景真实的绿色偏置（绿地板 + 绿窗帘的反射光） × ②所选 Velvia LUT 的 1.5–2.3× 色度放大 × ③欠曝把内容推进放大最强、噪声最大的低码值区。**

> 顺带确认：**管线本身的白平衡没有错** —— 同分支的白墙 DNG 实测 `R/G÷ASN = 0.9991`、`B/G÷ASN = 0.9980`（第三轮），
> 而这间屋子的墙在"白平衡后"是 0.88–0.93（偏绿 7–12%），说明**偏绿来自这个场景的照明**（地板是亮绿色、窗帘绿色），不是 WB 计算错误。

## 2. 灯场景 JPEG：**没有同心色带** —— 第三轮结论得到最终确认

同一张 DNG 的 App JPEG 与 Lightroom 截图对比（同口径径向色带强度）：

| 来源 | B/G 沿半径 std |
|---|---|
| DNG 原始数据 | 0.0104 |
| **App 自身 JPEG** | 目视**平滑无色带**（只有一圈平滑的青色光晕） |
| Lightroom 截图 | 0.0534（有明显同心色带） |

- App JPEG 的灯芯/内光晕比值 R/G = 0.985–0.992、B/G = 0.995–0.997 → **中性** ✅
- 外围暗部 R/G = 0.30–0.53、B/G = 1.03–1.23 → 与第 1 节同一机制（场景在暗部有轻微青绿偏置 × LUT 放大），属**平滑渐变**而非色带。

→ **同心彩环确实只出现在 Lightroom 的渲染里**（数据干净 4–5 倍、App 自己的 JPEG 也没有），第三轮结论维持不变。

## 4. 建议（按性价比）

1. **先做一次"无调色"对照**（最重要，5 分钟）：把设置里的 `目标 Log` 设为 **None**、`LUT` 设为 **None**，同一场景重拍。
   - 若暗部绿明显减轻 → 确认是 LUT 放大（本轮结论），按 §4.2 处理；
   - 若仍然很绿 → 那是场景照明的真实偏色（绿地板/绿窗帘），需要在拍摄端（换角度/补光）或后期（WB 微调）解决，管线无需改。
2. **不要把高饱和 LUT 用在"欠曝 2–3 EV 的暗场景"上**：本场景内容落在 LUT 低码值区（放大最强）。可考虑：
   - 该场景改用中性 LUT 或不加 LUT；
   - 或为 LUT 增加"强度"滑杆（现有 `apply_lut` 之后做 lerp 即可，改动很小）。
3. **降低默认欠曝**（产品决策）：低 ISO 下 `FACTOR_EV_MINUS_3 = 0.125`（−3 EV）使整幅画面依赖后期抬升，既放大噪点也让调色结果对 LUT 极其敏感。若该机型高光并不需要 3 EV 余量，**默认 −1～−1.5 EV** 会同时改善观感与稳定性。
4. **DNG 侧不需要再改**（本轮与第三轮均未发现 DNG 缺陷）；第二轮提出的"把 LSC 移回 Bayer 域"**无需执行**（已被白墙实测推翻）。
5. 若希望 JPEG 与 DNG 观感一致：用 DNG 在 Lightroom 里生成一个**中性相机配置文件**，或让 App 的标准路径（引擎 + 高光去饱和）出图后再由用户自行调色。
