## 5. 线程与生命周期（Invariant 4）

- 预检在 `Dispatchers.Default` 上求值：BatteryManager/PowerManager/ActivityManager 读取与 F5 的
  `CameraCharacteristics` 读取都在后台，主线程零阻塞；
- `ZslProbeHandlerDispatch.runBlocking` 的所有 `latch.await` 都在后台协程上下文；`camera2Handler`
  只做请求构建与提交；
- `ZslProbePreconditions` 零 Android 依赖、零副作用；
- R10 的 `consumePendingZslProbe()` 只做内存快照读 + `edit{}`（非阻塞 FIFO），不做磁盘 IO。

## 6. 已知偏差与风险

| # | 项 | 处理 |
|---|---|---|
| 1 | ~~`ImageReader` 无格式 API~~ **F1 已修正**：`getImageFormat()` 自 API 19 起可用，现有实现**无条件**读真实格式，不再有 SDK 分支 | 见 `ZslProbeRawReader.kt`；旧偏差记录保留以便审计 |
| 2 | 会话在探测中途被关闭时，`updateCamera2RepeatingRequestNow()` 返回 false → `endDualStream()` 报 "restore failed"，`Failed(CAPTURE_FAILED)` 优先于 `Aborted` | 沿用 S1-B1 F2 的优先级取舍（宁可报失败也不留下未还原的相机）；真机冒烟项 §7-6 覆盖"探测中退出相机页" |
| 3 | 冷启动时 `onSettingsHydrated()` 补消费（R10）可能早于会话配置；此时若存在上一进程残留的 `pending=true`，会得到 `Failed(PRECONDITION_FAILED)`（pending 已被消费） | R12 预检保证不碰硬件；用户重跑一次即可。真机上该路径仅在"设置页点检测后进程被杀"时出现 |
| 4 | `updateCamera2RepeatingRequestNow()` 需要 camera2Handler 线程（R1 要求），目前由适配器 `runBlockingOnHandler` 保证 | KDoc 已显式声明 |
| 5 | 非法报告 JSON 的"记录"是 `Log.w`（无遥测通道）；F5 的能力读取回落也记 `Log.w` | 与现有 probe 日志口径一致 |
| 6 | 适配器整体无 CI 单测（无可构造的真相机会话） | 真机验证项 §7；R4 用可替换的 handler 派发单元、F1 用可构造的 `ImageReader` 分类单元钉住关键语义，不自欺 |
| 7 | `ZslProbeReportStore.save` 由同步改 `suspend`（返回值 = 实际落库版本） | 调用方只有 Runner（后台上下文）；S1-B3 导入外部报告时同样需在协程内调用 |
| 8 | F5 重新读一次 `CameraCharacteristics`（binder IPC） | 只在预检时读一次、在后台线程；换取"未知 ≠ 不支持"的正确性 |
