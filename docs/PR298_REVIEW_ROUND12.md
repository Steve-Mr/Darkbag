## 3. 代码复核（`b4631444`）

### ✅ 修得对的地方

- **删除了 `ccm = colorMatrix1` 的错误覆盖**；新逻辑：
  ```kotlin
  val finalCcm = if (useSensorColorMatrix && singleCalib.renderCcm != null) singleCalib.renderCcm else ccmCapture
  // burst: val ccmSensor = burstCalib.renderCcm ?: ccmCapture
  ```
  ⇒ 渲染用 **ForwardMatrix 推导的 CCM**，并**保留 as-shot CCM 作为回退** ✅
- `useSensorColorMatrix` 的语义现在正确（"标定渲染 vs 厂商 as-shot"）✅
- `SensorCalibrationHelper.computeRenderCcm` 的**保中性原理成立**：DNG 规范中 `FM·(1,1,1) = XYZ(D50) 白`，再乘 `M_XYZ_D50→sRGB` ⇒ `(1,1,1)`；**与插值权重无关**，所以任何光源下中性都不会偏 ✅（这正是本轮实测 R/G≈0.99 的原因）
- 按 `calibrationIlluminant1/2` 取温度 ⇒ 对 GCam 那种**光源顺序相反**的 DNG 也能正确处理 ✅（GCam 的 CM1=Light A / CM2=D65，本机平台是 1=D65 / 2=A）

### ⚠️ 建议改进（按重要性）

1. **CCT 估计是经验式，且在本场景被 clamp 饱和**：
   ```kotlin
   val ratio = wbB / wbR                 // = ASN_B / ASN_R
   val cct = 2000f + ratio * 3500f       // 线性经验映射
   ```
   本场景 `ASN=(0.4313,1,0.6928)` → ratio **1.606** → cct **7622K** → mired 131 →
   `weight=(131−350.1)/(153.8−350.1)=1.115` → **clamp 到 1.0 ⇒ 实际只用 FM1(D65)**，
   双光源插值在这类"日光型中性"场景下**从未生效**。
   更本质的问题：`ASN_B/ASN_R` 是**传感器相关量**，不是通用 CCT 代理（换机型/换传感器即失准）。
   **建议**：由中性色的**色度**推 CCT（`xy = chromaticity(inv(CM)·ASN)` → McCamy 公式），或在 mired 域按两端光源的**色度距离**加权；并把最终 `weight` 打进日志，便于回归。

2. **规范细节：FM 的定义域**是"以**参考中性**归一化的相机坐标"（`raw/ReferenceNeutral`），当前把 FM 直接作用在 `raw/ASN`（场景中性）上。
   保中性不受影响 ✅，但**高饱和色**的再现会随光源失配漂移。
   **建议**：补 `diag(1/ReferenceNeutral)`（`ReferenceNeutral = inv(CC)·(FM⁻¹·XYZ_D50_白)`，CC=I 时即为 `FM⁻¹·XYZ_D50_白`），并用色卡 `[需实测]` 量化改善；若不便实现，至少在文档中标注该近似。

3. **B/G 与 GCam 的差距**（§1）需要一次**同亮度**对照才能定性：建议拍一组**白墙/灰卡**，把 Darkbag 与 GCam 的输出**归一化到同一亮度**再比 B/G；若仍差，则是 FM 权重/曲线问题，而非场景。
